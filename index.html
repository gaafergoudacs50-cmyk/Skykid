Skykid – smart motorized telescope

A two-axis alt-azimuth telescope on a tripod, driven by two geared stepper motors and an ESP32. Pick an object on your phone, and the mount slews to it and keeps it centered. The simulator below runs the real pointing math.

Tap the Bluetooth icon to connect, pick an object, then tap the button on the phone. The tube and base dot move as the motors would.

Connect your telescope to begin.

Planet positions use low-precision orbital elements (about 1° accuracy). The Sun is left out on purpose: never point a telescope at it without a certified solar filter.

Embedded systems: ESP32 motor control

The ESP32 turns pointing commands into smooth motor movement.

What to build

  • ESP32-S3 with two TMC2209 drivers and two NEMA 17 motors
  • AccelStepper for smooth speed changes
  • Bluetooth receives the target, then alt/az is computed 10 times a second
  • Homing with hall sensors, soft limits at 90° altitude and ±270° azimuth
  • 192,000 steps per turn, so 0.0019° per step

Done when

The mount homes itself, slews to a target and holds it without drifting.

AI computer vision tracking

A camera lets the telescope see where it really points.

What to build

  • Raspberry Pi and a low-light camera such as the IMX290
  • OpenCV finds stars and the target in each frame
  • Plate solving (ASTAP) replaces the manual “Sync here” step
  • Pixel error becomes degrees: scale = 206.265 × pixel µm ÷ focal mm
  • The Pi sends small corrections to the ESP32 as C,dAz,dAlt

Done when

The target stays centered for 30 minutes without touching the app.

Mechanical design: mount and 3D print

A solid, balanced alt-azimuth mount that anyone can print.

What to build

  • Tripod, rotating base ring, fork arm and tube
  • 60:1 worm gear on each axis, so it holds position with power off
  • Print in PETG or ASA at 0.2 mm with 4 walls
  • Balance the tube on its trunnions before adding motors
  • Route cables through the hollow azimuth shaft

Done when

The tube moves smoothly by hand and does not sag when released.

Astronomical data and calculations

The math that turns a sky position into motor angles.

What to build

  • Start with RA and Dec of the target
  • Compute local sidereal time from the date, time and longitude
  • Convert to altitude and azimuth for the observer’s latitude
  • Planets come from orbital elements, accurate to about 1°
  • Repeat every 0.1 s, and that is tracking

Done when

The mount’s answer agrees with a planetarium app to within 1°.

Control systems

Make the motion smooth, accurate and stable.

What to build

  • Acceleration ramps, so the heavy tube never jerks or skips steps
  • A tracking loop that refreshes the target 10 times a second
  • Shortest-path azimuth moves with a ±270° limit
  • Optional closed loop: the camera error nudges the target with a small gain
  • Safety: limits, stall detection and a stop command

ESP32 firmware (reference sketch, untested on hardware)

Arduino framework with the NimBLE-Arduino and AccelStepper libraries. The phone writes T,raDeg,decDeg,latDeg,lonDeg,unixSeconds to the RX characteristic. X stops tracking.

#include <NimBLEDevice.h>
#include <AccelStepper.h>
#include <math.h>

#define SVC "6e400001-b5a3-f393-e0a9-e50e24dcca9e"
#define RX  "6e400002-b5a3-f393-e0a9-e50e24dcca9e"
const float STEPS_PER_DEG = 200.0 * 16 * 60 / 360.0;  // 533.3
const float R = M_PI / 180.0;

AccelStepper az(AccelStepper::DRIVER, 25, 26);
AccelStepper alt(AccelStepper::DRIVER, 27, 14);

volatile bool tracking = false;
double ra, dec, lat, lon, unix0;
uint32_t ms0;
float azNow = 0, altNow = 0;   // degrees, set to 0 at the home mark

void altAz(double t, float &A, float &h) {
  double jd = t / 86400.0 + 2440587.5;
  double lst = fmod(280.46061837 + 360.98564736629 * (jd - 2451545.0) + lon, 360.0);
  double ha = (lst - ra) * R, d = dec * R, p = lat * R;
  double s = sin(d) * sin(p) + cos(d) * cos(p) * cos(ha);
  h = asin(s) / R;
  A = fmod(atan2(sin(ha), cos(ha) * sin(p) - tan(d) * cos(p)) / R + 180.0 + 360.0, 360.0);
}

class Rx : public NimBLECharacteristicCallbacks {
  void onWrite(NimBLECharacteristic *c) override {
    std::string v = c->getValue();
    if (v[0] == 'X') { tracking = false; return; }
    if (sscanf(v.c_str(), "T,%lf,%lf,%lf,%lf,%lf", &ra, &dec, &lat, &lon, &unix0) == 5) {
      ms0 = millis();
      tracking = true;
    }
  }
};

void setup() {
  pinMode(33, OUTPUT); digitalWrite(33, LOW);          // enable drivers
  az.setMaxSpeed(4000);  az.setAcceleration(3000);     // about 7.5 deg/s
  alt.setMaxSpeed(4000); alt.setAcceleration(3000);
  NimBLEDevice::init("Skykid");
  NimBLEServer *s = NimBLEDevice::createServer();
  NimBLECharacteristic *c = s->createService(SVC)->createCharacteristic(RX, NIMBLE_PROPERTY::WRITE);
  c->setCallbacks(new Rx());
  s->getServiceByUUID(SVC)->start();
  NimBLEDevice::getAdvertising()->addServiceUUID(SVC);
  NimBLEDevice::getAdvertising()->start();
}

void loop() {
  static uint32_t last = 0;
  if (tracking && millis() - last > 100) {           // 10 Hz target update
    last = millis();
    float A, h;
    altAz(unix0 + (millis() - ms0) / 1000.0, A, h);
    if (h > 0) {
      float d = fmod(A - fmod(azNow, 360.0f) + 540.0f, 360.0f) - 180.0f;  // shortest way
      azNow = constrain(azNow + d, -270.0f, 270.0f);
      altNow = constrain(h, 0.0f, 90.0f);
      az.moveTo(azNow * STEPS_PER_DEG);
      alt.moveTo(altNow * STEPS_PER_DEG);
    }
  }
  az.run(); alt.run();
}
